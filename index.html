✅
Pipeline visual en tiempo real
Los 5 nodos del pipeline se iluminan secuencialmente y el log muestra cada acción. El usuario sabe en todo momento qué agente está trabajando — cumple el principio de visibilidad del estado del sistema (Nielsen #1).
✅
API Key persistente y segura
Guardada en localStorage, se recupera automáticamente al recargar. El campo es tipo password con botón mostrar/ocultar. El usuario no tiene que volver a escribirla en cada sesión.
✅
Drag & Drop de archivos con feedback inmediato
La zona resalta al arrastrar, muestra progreso de extracción con estado (⏳/✓/✗) y el número de caracteres extraídos. Acepta múltiples archivos PDF y Word simultáneamente.
✅
Tema claro / oscuro con persistencia
Toggle en cabecera, preferencia guardada en localStorage. El tema claro mejora la legibilidad en entornos con luz ambiental alta (despachos, aulas).
⚠️
Sin validación en tiempo real de los campos obligatorios
El botón "Iniciar Pipeline" solo valida al pulsarlo. El usuario no sabe si falta la asignatura o la lista de estudiantes hasta el momento de ejecutar, lo que obliga a desplazarse para localizar el campo vacío.
→ Mejora: marcar con borde rojo los campos obligatorios vacíos al perder el foco (evento blur). Añadir contador de alumnos en tiempo real ya resuelve parcialmente esto.
⚠️
No hay estimación de tiempo ni coste de API
Con 30 estudiantes y material extenso el pipeline puede tardar 3–5 minutos y consumir ~$0.15 en API calls. El usuario no tiene esa información antes de lanzar.
→ Mejora: calcular y mostrar estimación de tokens y coste aproximado justo encima del botón principal, antes de ejecutar.
✅
Botón Cancelar pipeline
El botón "✕ Cancelar pipeline" aparece durante la ejecución. Al pulsarlo se activa un flag que detiene el pipeline al terminar la llamada API en curso, evitando cortar una petición a la mitad y dejando el estado corrupto.
✅
Contraste WCAG AA corregido
--muted subido de #6b6b80 a #8a8aa0 en tema oscuro. Ratio de contraste ~5.2:1 (supera el mínimo de 4.5:1). Afecta a labels, hints, contadores de caracteres y textos secundarios.
✅
Responsive móvil implementado
Media queries a 768px y 480px: grid pasa a 1 columna, pipeline se orienta verticalmente, agent-badges ocultan salvo la activa, stats-row usa 2 columnas, resultados y acciones se apilan correctamente.
✅
ARIA completo y navegación por teclado
Tabs con role="tab"/role="tabpanel"/aria-selected, panel colapsable con aria-expanded, botones con aria-label, campos con aria-required/aria-invalid, progressTag con aria-live="polite", estimación de coste con aria-live="polite".
✅
Validación en tiempo real de campos obligatorios
API Key, Asignatura y Lista de estudiantes muestran borde rojo + mensaje de error al perder el foco (blur) si están vacíos. El error desaparece al escribir. aria-invalid se actualiza en sincronía.
✅
Estimación de coste y tiempo antes de ejecutar
Al escribir estudiantes se muestra automáticamente: nº de llamadas API, tokens estimados, coste en € y tiempo aproximado. Se recalcula al cambiar modelo, nº preguntas o tamaño del material. El coste se resalta en naranja si supera €0.50.
✅
PDFs multipágina según número de preguntas
El selector de preguntas usa múltiplos de 10. Cada grupo de 10 genera exactamente 1 hoja A4 horizontal (5×2). 20 preguntas → 2 hojas, 30 → 3, etc. La página 1 lleva instrucciones; las siguientes muestran "Continuación — Pág. N/Total".
